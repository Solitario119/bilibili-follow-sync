# bilibili-follow-sync（B站关注同步）

把一个B站账号的关注列表**同步**到另一个账号（典型场景：主号 → 小号），也可以用来
**备份**关注列表。提供三种形态：**桌面版**（推荐，双击即用）、**油猴脚本**
（浏览器即用）和 **Python CLI**（进阶用户）。

> 没有任何官方功能支持这件事；现成开源项目里也只有"批量取关"，没有"跨账号同步"。

## 安装

**桌面版（推荐，双击即用）**：从 [Releases](../../releases) 下载 `BiliFollowSync.exe`
双击运行即可，无需装 Python 或浏览器扩展。

**油猴脚本**：
1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展
2. 从 [Releases](../../releases) 下载 `bili-follow-sync.user.js`，在 Tampermonkey
   「添加新脚本」粘贴全文保存（或把文件直接拖到 Tampermonkey 图标上）

**Python CLI**：见下文「使用方法（Python CLI 版）」。

## 使用方法（桌面版）

1. 启动程序，**主号**与**小号**分别点击「扫码登录」，使用B站手机客户端扫码
   完成登录（亦可通过「粘贴Cookie」登录）。登录凭据仅保存在本机，不经过任何第三方
2. 点击 **「开始同步（主号 → 小号）」**：自动拉取双方关注列表并比对差集，
   仅关注小号缺失的用户，并按主号的分组设置自动归组
3. 其余操作：
   - **「备份关注列表」**：将主号关注列表（含分组信息）导出为 JSON 文件
   - **「反向清理」**：取关小号上主号未关注的用户。执行前完整展示待取关
     名单并要求确认，默认保护小号的特别关注
4. 右上角「设置」提供关注间隔、每日尝试上限、深色模式与日志文件夹入口

窗口底部状态栏实时显示当日尝试进度；限速、风控自动停止、断点续跑等
保护机制与油猴/CLI 版一致。

## 功能特性

- ✅ **导出**：一键把当前账号的全部关注导出为 JSON 备份（含用户名、mid 与分组信息）
- ✅ **同步**：在另一个账号导入该文件，自动比对差集，只关注缺失的用户
- ✅ **分组保留**：特别关注与自定义分组随同步一起保留——小号自动创建同名分组并归入
- ✅ **反向清理（可选，危险）**：取关小号上主号没有的关注；完整名单预览 + 双重确认，
  默认保护小号的特别关注（CLI `--clean` / 面板「④ 反向清理」按钮）
- ✅ **定时自动备份**：油猴脚本每天首次打开关注页自动备份到浏览器本地（保留最近
  30 份，面板「📦 历史备份」可下载）；CLI `--backup` 配合任务计划程序定时落盘
- ✅ **幂等可续跑**：任何时候中断（手动停止 / 触发风控 / 关掉浏览器），重新导入
  同一文件即可从断点继续，已关注的自动跳过，永不重复
- ✅ **风控保护**：默认 3秒/个 限速、每日尝试上限（B站软配额约 300 次/天）、
  被拦截自动停止——实测参数见 [docs/risk-control-notes.md](docs/risk-control-notes.md)
- ✅ **不碰账密**：只用B站客户端扫码/本机登录态，凭据不经过任何第三方

## 使用方法（油猴脚本版）

1. 按上方「安装」一节装好脚本
2. **主号**：浏览器登录主号 → 打开 `自己的个人空间 → 关注` 页面
   （形如 `space.bilibili.com/你的UID/relation/follow`，旧版为 `/fans/follow`）→ 点击面板上的
   **「① 导出本账号关注列表」**，得到 JSON 文件（含特别关注/自定义分组）
3. **小号**：登录小号，打开同样的关注页面 → 点 **「② 选择导出文件并比对」** →
   确认待关注人数 → 点 **「③ 开始同步」**
4. 面板会实时显示进度和日志；被风控自动停止时，明天重新执行第 3 步即可
5. **反向清理（可选）**：点 **「④ 反向清理（取关多余）」**，会重新拉取小号最新
   关注列表、列出"主号没有的关注"，确认后逐个取关；默认保护小号的特别关注。
   这是删操作，请先看清名单再确认
6. **自动备份**：每天首次打开关注页，脚本会自动把关注列表快照存到浏览器本地
   （保留最近 30 份，仅当前浏览器可见）；点 **「📦 历史备份」** 可随时下载某份
   快照。完整含分组的备份仍请定期用「① 导出」保存到本地文件

## 双向同步

现有导出/导入天然支持任意方向：想把小号的关注也同步给主号，**反向跑一遍即可**——
小号导出 → 主号导入。CLI 版把 `MAIN_COOKIE` / `ALT_COOKIE` 内容互换再跑一次。

## 使用方法（Python CLI 版）

> CLI 入口依赖 `core/` 包，请先 `git clone` 本仓库（或下载仓库 ZIP 解压）。

```bash
pip install requests
# 编辑 cli/bili_sync_follows.py 顶部的 MAIN_COOKIE / ALT_COOKIE
# （F12 → 网络 → 任意 bilibili.com 请求 → 复制整串 Cookie）
python cli/bili_sync_follows.py
```

CLI 版同样支持分组保留：同步时自动拉取主号的特别关注/自定义分组，在小号上
创建同名分组并归入。反向清理用 `python cli/bili_sync_follows.py --clean`
（默认保护小号特别关注，`--no-protect` 关闭）；双向同步则把两个 Cookie 互换
再跑一次。

**定时备份（Windows 任务计划程序示例）**：

```bash
python cli/bili_sync_follows.py --backup             # 备份主号到 cli/backups/
python cli/bili_sync_follows.py --backup --account alt   # 备份小号

# 每天 09:00 自动备份（注意 /TR 里 python 和脚本都要用绝对路径）
schtasks /Create /SC DAILY /ST 09:00 /TN "bili-follow-backup" ^
  /TR "C:\Python312\python.exe F:\path\to\cli\bili_sync_follows.py --backup"
```

## 重要：B站风控与每日配额

B站对关注操作有 **约 300 次/天的软配额**（实测两天均在第 299 个成功后被拦截）。
超配额后当天所有关注请求都会返回 `22015 风控拦截`，且**加速、暂停、放慢都无法
绕过**，只能等次日恢复。因此：

- 同步几百个关注请计划分 2~3 天完成
- 不要在小号上手动抢跑，配额是共享的
- 触发拦截后本工具会自动停止并提示，明天重跑即可
- 归组写入（创建分组、移入分组）按保守策略同样计入本工具的每日尝试计数

## FAQ

**会被封号吗？** 实测只会触发"当日限额"（返回 22015），未观察到封号或功能受限。
但自动化操作违反B站用户协议的风险理论上存在，请自行评估，仅供个人学习交流使用。

**会把小号已有的关注取消吗？** 默认不会。同步只做"新增缺失的关注"；只有你显式
点「④ 反向清理」（CLI 为 `--clean`）才会取关小号上主号没有的用户——该操作有
完整名单预览和双重确认，默认保护小号的特别关注，且每次最多执行每日安全上限。

**想双向同步（两边互相补齐）？** 把流程反向跑一遍即可：小号导出 → 主号导入。
详见上方「双向同步」一节。

**主号列表里有已注销的账号？** 会自动识别（`22013`）并跳过，不影响其他用户。

**特别关注/自定义分组会同步吗？** 会。导出文件里带分组信息，同步后
小号会自动创建同名分组并把对应的人归入；"悄悄关注"属于私密数据，不会同步。
注意：只对**本次新关注的人**归组，同步前就已在小号关注列表里的人不会补归组。

**想反向清理（小号取关多余的）？** 支持，见使用方法第 5 步。

**旧版本的导出文件还能用吗？** 能。v1 文件（不含分组）导入后行为与旧版一致，
只是不做归组；新导出的 v2 文件在旧版脚本里也能导入（忽略分组）。
